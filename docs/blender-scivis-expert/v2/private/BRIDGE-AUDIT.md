# Scientific visualization bridges: evidence review and consolidation

Private working analysis, 17 November 2026. This subtask read the complete three
attached files. It did not access the private repository, recover its kits or
rerun the historical 52-agent workflow. The machine-readable
`bridge-catalog.json` preserves the original source locations, grades, input
paths, criteria and verifier objections for all 18 bridges, and adds the nine
critic candidates as proposals. Its hashes identify the exact attachments.
The companion `current-evidence-map.json` compares actual retained Research
Loom bytes with these proposals; it does not turn historical numbers into new
measurements.

The strongest idea survives review: use numerical data, declarative scenes,
authoring tools and independent readback as cooperating instruments. The main
weakness is the reuse of a single confidence label for an entire bridge. One
bridge can contain an inspected implementation, an unretained timing, a planned
patch and an unrun acceptance criterion. Those are four different claims.

## What to retain, correct and combine

Retain the separation between schema legality, visible output, completeness and
scientific fidelity. Preserve the source-scene loss audit before export, the
known-answer fixture factory, the renderer-independent splat oracle, explicit
per-field tolerances and the insistence on exact version identities. These are
reusable across STEM, mathematics, molecular rendering, heritage and gameplay.

Correct the impression that the bridges are largely ready-made wrappers.
The document itself records hard-coded scratch paths, missing fixture packs,
conflicting commit pins, unrun pass criteria and import-time remote calls.
The work is primarily interface definition, evidence recovery and scope control.
That is worthwhile engineering; disguising it as wiring would conceal the
important work.

Combine overlapping ledgers instead of building new ones for each domain.
B10 supplies scientific cases; B11 supplies corpus selection; B04/B06/B27
supply value and appearance tests; B12 supplies provenance; B05/B14 supply
workflow adapters. They should share identities and findings while retaining
their different responsibilities.

## Ordering that avoids duplicated work

Start with B24, even though it appeared near the end of the original catalog.
The earliest useful result is a recoverable baseline, not another headline
benchmark. Source files described in a document are not recovered artifacts.
Recover the exact bytes, record hashes, classify executable side effects and
make old result files read-only inputs to the review. Recreated output must be
labelled as a new run.

Then finish the smallest reusable contract: one scientific fixture, one source
packet, explicit scientific-to-display mappings, named export projections,
readback findings and an actual output receipt. Research Loom already provides
this pattern for three non-splat studies. Extend it with one ordinary point/line
regression and one asymmetric precision/origin case before expanding the corpus.

Keep B02 and B03 as coordinated alternatives for different failure modes.
An honest resource-limited validator verdict remains useful even when partitioned
exports avoid a parser limit. A larger parser allowance does not prove the XSD
engine can validate every large attribute. Byte budgets should be per actual
encoding and field, with a measured refusal outcome.

Do not block small-scene work on B02. B05's guard prototypes used small exports,
and B09's scientific probes can run independently of huge-splat support. Likewise,
B10 fixture authoring and B06 baseline capture can begin before B04 importer
repairs. Only an acceptance criterion that expects repaired values depends on
the repair. The catalog records hard, conditional and removed dependencies
separately.

After values and representation are stable, run larger corpus tiers and native
splat/codec paths. Workflow orchestration comes after stable command contracts.
Model benchmarks come after a pre-registered selector, a held-out split, calibrated
oracles and a defined budget. A stub workflow can be useful much earlier, as
long as its stubbed stages are explicit.

## Taxonomy: classify by meaning and failure mechanism

Use multiple orthogonal facets instead of one deep folder tree.

| Facet | Suggested values | Why it matters |
|---|---|---|
| Scientific role | observation, model parameter, derived quantity, uncertainty, assumption | Distinguishes a measured point from an authored glyph radius |
| Representation | raw array, mesh, centerline, point glyph, volume, splat, semantic graph | A useful display representation need not preserve analytical operations |
| Transformation | solver, resampling, coordinate change, projection, quantization, authoring, rendering | Makes losses attributable to a particular operation |
| Data space | physical/model coordinates, display coordinates, world coordinates, linear RGB, encoded RGB, opacity, logit | Prevents an error bound being quoted in the wrong space |
| Gate | syntax, schema, semantic rule, model witness, numerical reference, retention, render, rights policy | Prevents an XSD pass from becoming a scientific claim |
| Evidence status | described, recovered, inspected, executed, reproduced, superseded, unavailable | Records what was actually done rather than inferred from a grade |
| Failure mechanism | omitted, reordered, quantized, remapped, stale, truncated, resource-limited, unsupported, assumption-violated | Gives repair tools a concrete target |
| Scope | fixture, bounded subset, corpus partition, declared profile, arbitrary file | Blocks narrow-fixture results from being generalized silently |
| Rights | explicit grant, restricted, absent, conflicting, unresolved | Keeps legal facts separate from a versioned eligibility decision |

Domain tags can then connect structural biology, volumes, geoscience, dynamics,
acoustics, heritage, game mechanics and mathematics without duplicating the
same color/precision/provenance rule in every domain folder.

## Ontology hooks to add, without inventing a second ontology

The following are proposed modeling hooks. Use a small local vocabulary for
new scientific concepts and align existing standards when their precise
versions are chosen. Namespace labels here are design references, not evidence
that those schemas or validators have been implemented.

| Entity or relation | Required information | Candidate alignment |
|---|---|---|
| ScientificCase | question, assumptions, domain, source identity, units | Local case vocabulary; `prov:Entity` for provenance |
| Quantity | value/array, quantity kind, unit, coordinate frame, uncertainty | QUDT/SOSA where suitable; domain vocabulary for pLDDT/PAE |
| Representation | authoritative case, displayed quantity, exaggeration, glyph map, color map | `prov:wasDerivedFrom`; local projection/encoding vocabulary |
| Transformation | inputs, tool/build, parameters, output hashes, expected losses | `prov:Activity`, `prov:used`, `prov:wasGeneratedBy` |
| Witness | statement, observed value, bound, rule, method, scope, status | Local scientific witness; distinguish from SHACL validation |
| ValidationAttempt | exact candidate, profile, instrument, result, refusal reason | SHACL report alignment for graph constraints; XSD metadata for XML |
| RetentionMeasurement | source field, destination field, numeric space, error, tolerance | Local exchange contract and measurement vocabulary |
| RenderConfiguration | renderer/build, camera, lighting, display transform, sampling | Provenance activity plus local camera/color/sampling terms |
| Figure | case/state, render derivation, image bytes/pixel hash method | Provenance entity; explicit raster/EXR sidecar asset relation |
| RightsAssertion | asserted licence, source, evidence date, uncertainty | `dct:license`, rights-holder attribution; versioned policy separately |
| FailureFamily | minimal reproducer, causal category, held-out membership | Local QA taxonomy, links to rules and affected capabilities |
| BridgeProposal | owner, inputs, scope, dependencies, maturity, adoption status | Local planning ontology; links to implemented activities rather than becoming one |

The useful graph joins are concrete: a failing retention measurement points to
the source field, the export activity and the destination representation; the
fixture that discovered it links to the corrected rule; a later run uses that
rule and cites the fixture without claiming that the discovery set is held out.
Legal-parent ontology lookups establish graph legality, while numeric witnesses
establish different claims about coordinates, weights and quantities.

## Heuristics worth institutionalizing

1. **The unit of confirmation is a scoped claim.** A bridge, repository or
   application does not receive a blanket confidence upgrade.
2. **Keep the data authority explicit.** Unexaggerated arrays and quantities
   remain authoritative when an attractive mesh is stretched, colored or lit.
3. **Read the thing that could be wrong.** Metadata identity checks cannot
   detect a changed Blender vertex; retained geometry metadata cannot stand in
   for decoded coordinates; an exported render cannot prove a legend.
4. **Compare in the declared space.** Quaternion sign, logit/alpha conversion,
   linear/encoded color and global/local coordinates each need their own metric.
5. **Expected loss is a contract, not an excuse.** A declared projection can
   pass while losing unsupported semantics, but its label must prevent reuse as
   a complete scientific round trip.
6. **A refusal is information.** Unsupported data, a resource cap and a
   validator exception should be distinguishable from invalid science.
7. **Freeze before fixing.** Baseline and repaired results must share fixtures,
   scope and instruments apart from the intended change.
8. **Use cheap exact checks first.** Counts, coordinate transforms, arrays,
   topology, units and known-answer fields precede image judges and model calls.
9. **Oracle disagreement is a result.** Record which semantics differ; do not
   reduce validation, drawing and data fidelity to a single average score.
10. **Derivation is not authenticity.** Hashes identify bytes and chains record
    relationships; signatures and authenticated provenance are separate layers.
11. **Schema-valid output can launder lost input.** Validate input, audit source
    capabilities, compare output meaning and retain every refusal/loss.
12. **Workflow simplicity is a research feature.** Thin local wrappers and
    durable identities make failures inspectable before an agent graph is added.

## Future experimental program

The first pack should contain ordinary point/line geometry, an asymmetric
tetrahedron, a known color ramp with a legend, a large-origin/small-offset
coordinate case, one SH0/SH3 splat pair and an explicitly failing control for
each gate. It should use one manifest and one findings vocabulary, while each
consumer declares its own supported subset. Current Research Loom supplies the
first two categories and a tested data/geometry/render separation; the remainder
requires actual fixtures.

The next domain packs are an anisotropic volume phantom (B19), a tiny molecule
with stable identities (B20), a CRS/local-origin terrain sample (B21), fixed-
fraction animation (B22) and an HAnim hierarchy/skin control (B23). Domain
meaning must be testable before presentation detail is increased. A pLDDT ramp
must be tied to a prediction source; a generic crystallographic B factor should
not be silently reinterpreted as pLDDT.

Only after those contracts exist should B18 compare authoring lanes. Select
feasible prompts by explicit capabilities, use matched tasks and budgets, keep
held-out material separate, report valid/draws/complete/retained/data-correct
stages independently, and calibrate presentation order for any judge panel.
The original estimated cost and old percentage baselines do not authorize or
justify a new online experiment.

The five historical user questions are now actionable defaults rather than
reasons to stop local work: keep exact per-run validator identities; preserve
recoverable evidence privately; refresh the native-splat capability probe;
offer named appearance/comparison profiles; and prepare reviewable patch kits
for owning repositories without sending them. The private access and source
availability question remains material because several high-value kits may
exist only in the named branch. That gap should be stated precisely, with the
attached summaries still used as a backlog and evidence map.
