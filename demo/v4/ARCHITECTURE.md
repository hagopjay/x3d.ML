# Tether Firehose 4 — ARCHITECTURE (the frozen contract for wave 2)

Lead, wave 1, 24 Oct 2026. This file wins over `WORKPLAN-v4.md` where they differ; `SPEC-v4.md` stays the content spec. Every wave-2 agent reads this file for the contract and nothing else. Globals, hooks and file names below are frozen; a wave-2 module may add to its own namespace, never to another's. Where a WORKPLAN interface line changed, the change is called out as **changed:**.

## 0. Ground truths you must not re-decide
- Dark first; one rAF loop (`LOOP`); no `setInterval` anywhere in the bundle (the build and `check_v4.py` count it: must be 0); no `innerHTML` on a timer; canvas for any panel over 200 marks; tokens through `cssv()`; dpr through `fitCanvas()`.
- The bundle is ONE classic `<script>`: `js/NN-name.js` concatenated in filename order. Top-level declarations are therefore shared across modules, so **every module is an IIFE** (`(function(){ ... })();`) and exposes exactly its documented globals as `self.X = ...` (works in page and worker). Never declare a top-level `const/let/function` outside your IIFE. Module-level side effects allowed: `LOOP.register`, `CLAIMS.define`, `MODES.register`, `SECTIONS.register`, `TOUR.push`, `DATA.on`.
- Every module file starts with a header comment: what it owns (SPEC §), globals exposed, test hooks (`__name`), and the v3 line range it ported (`demo/tether-firehose-v3.template.html`).
- Parts are gzip+base64 own files (`parts/<name>.txt`) decoded with `DecompressionStream("gzip")` (fflate 0.8.2 from cdnjs only when `DecompressionStream` is missing); every part is checked against `MANIFEST.parts[name].sha256` (sha256 of the decoded bytes, computed in the hash worker or `crypto.subtle` on the main thread) and refused on mismatch.
- Honest labelling: every number is a claim chip (`claimChip(id)`), every section header carries the three stamps and a grade (`sectionHeader`), staged renders say STAGED, the measured frame is the frame the numbers count.
- The build greps bundle + workers + jsval for `new Function` and `eval(` and refuses on any hit **except lines tagged `/*@env-probe*/`** (exactly two exist: one in `js/06-env.js`, one in `workers/probe.js`; the build prints the count and refuses if it is not 2).
- Nothing on the page calls a network host other than its own files (plus Google Fonts CSS and the optional fflate fallback from cdnjs). `api.openai.com` is never called by anything.

## 3. Boot order (99-boot.js)
1. `THEME.init()`, `FX.init()` (reads renderer later; `?lite=1`, `navigator.webdriver`, width, reduced motion decide the first level) → `html[data-fx]`, `html[data-theme]`.
2. `ENV.probe()` (async; nothing waits) → `ENV.ready`; `FX.set()` re-evaluated when the renderer is known.
3. `TIER.resolve()` (async; nothing waits) → `TIER.ready`; `TIER.badge(#tierBadge)`.
4. `SECTIONS.mountAll()` in template order: each registered section's `mount(sectionEl)` runs once with the section's `.sh` already filled from its `header` spec. A section whose `data-tier` is above the resolved tier is removed from the DOM when `TIER.ready` settles (never a stub).
5. `CURTAIN.start()` (skipped at fx 0).
6. `STAGE.init()` when X_ITE is ready (`window.X3D`, polled by `later`), creates `STAGE.measure` and `STAGE.show`; `STAGE.ready` resolves; `CURTAIN.lift()` on the first show frame or at 2.5 s.
7. `DATA.start()` loads parts in §8 order (`live.core, events, live.bodies, replay, renders.series, renders.151, drift, suite, live.jpg`; `xsd40/xsd41` only on `VAL` demand), each firing `DATA.on(name)` listeners; `SIM.fresh('live17')` runs as soon as `live.core` + `live.bodies` are in (`SIM` needs bodies for the chains).
8. `LOOP.start()` (the rAF loop runs from step 1 so panels can draw placeholders; `SIM.step` is attached by 20-sim).
9. `VAL.init()` lazy (M4 decides eager at fx ≥ 1).
10. Global hooks: `window.onerror` / `unhandledrejection` append one line each to `#under .errors` (X_ITE's wasm/stylesheet fetch rejections are swallowed as in v3).

### 04-prov.js — globals (v3 names kept): `contentHash`, `addStep`, `readSteps`, `readSeal`, `verify`, `revalidateOne`, `provJson`, `olJson`, `otlpJson`, `spansOf`, `sha256b`, `sha`, `hmac`, `stripProv`, `SECRET`, `ZERO`, `dumps`, `injectMeta`, `setStepJson`, `HASH`
- Ported from v3 lines 266–336 (SHA-256, HMAC, x3dprov core), 641–650 (provJson, olJson, otlpJson), 586 (spansOf), 468 (revalidateOne). Valid as a page script and as a worker body (no DOM, no `window`; everything on `self`). Ops set extended with `ingest, measure, judge, summary, transform`.
- `spansOf(sc)`: `ms = r.ms ?? r.latency_ms ?? 0`, `src = r.ms_src || (r.ms ? "recorded" : "missing")`; nothing is modeled in v4 (**changed:** v3 drew random modeled durations).
- `revalidateOne(sc, V)`: `V` is a `VALS` entry; the verdict comes from `self.judge(sc, V)` (defined by 20-sim); returns true on a valid→invalid flip.
