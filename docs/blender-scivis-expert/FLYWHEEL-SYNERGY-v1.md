## 1. Thesis

PolyXandria is the place where the pieces that already turn separately meet in one loop: the x3d_mcp fork (exact validator plus Playground), the x3d-blender-io fork (the only modern Blender X3D path and the only splat exporter), the ontology (legal-parent and HAnim lookups), compact encodings, the DSPy/red-team programme, the agent loops, the AI-vision judges and the Library's 3,058-scene spine. The Blender sci-vis expert adds what none of them has: a second renderer and exact oracles (Cycles, BVH contact, ID masks), a source of known-answer sci-vis fixtures the Library cannot supply (0 clean valid PointSet, ColorRGBA, MetadataFloat or volume scenes; 5 clean splat scenes, SH0 only), and a guard for the Blender-agent lane. In return Blender gets the validator as a pre-import and post-export gate, the spine as a 585-scene on-disk importer regression set, mutants as fuzz input, X_ITE-exact look and animation oracles, and provenance that survives its round trip. Splats are the first and best-proven wire (PLY to X3D 4.1 to Blender to PLY is float32-exact on bpy 5.2.3, with measured walls and ordering traps). The main missing pieces are instrumentation and wiring, not new science: per-hop metrics, a durable fixture suite, a Blender-side loss audit, and a LangGraph graph that calls the existing scripts as nodes. Almost all of it runs at $0 in this container (bpy 5.2.3, fork validator, headless Chromium X_ITE 16.5.1), and most fork changes are handoffs to the in-flight Blenderization and Playground threads, not new builds.

## 3. Six loops that turn it

- L1 Splat loop (first): Cycles render of X3D master -> gsplat -> x3d-blender-io export with slabs -> fork + upstream validators -> X_ITE vs numpy oracle vs Blender mesh/5.3 native -> PSNR split synthetic/real, size by SH degree -> fixes into exporter, validator and compact-encoding rules.
- L2 Importer/exporter defect loop: Library corpus (585 on-disk, Tier A 111) + spine mutants -> round-trip ledger -> value-level defects (colour, defaults, crashes) -> Blenderization fixes -> better Hall renders and calibration -> sharper fixtures.
- L3 Tether/guard loop: Blender agent script -> loss audit -> export -> pinned validator -> X_ITE + Blender render -> ledger step -> failures become loss-audit rules, lints and ladder rungs, which gate the next agent script.
- L4 Oracle ladder loop: computed oracles (ID mask, blank cause, splat oracle, BVH) take over from judges, so judge noise (second image wins 60%, ~1/3 order flips) stops being the bottleneck; the residual goes to the panel.
- L5 Red-team loop: DSPy attacker with V + X + B + D finds valid-but-wrong scenes on demand; each class gets a minimal reproducer, a static classifier rule and a fixture, then a validator lint (Playground) - the number of open loopholes is the stop rule.
- L6 Provenance/Library loop: every hop (generate, export, validate, render, judge) is an x3dprov step; accepted scenes and figures are written back to the Library with lineage and licence passport, growing exemplars, mutants and curricula.
